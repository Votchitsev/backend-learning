# libuv Filesystem

Первоисточник: [libuv File I/O / Filesystem](https://docs.libuv.org/en/v1.x/guide/filesystem.html). Сверено 14.10.2026 по документации ветки v1.x; актуальный выпуск ветки на дату сверки — [libuv v1.53.0](https://github.com/libuv/libuv/releases/tag/v1.53.0).

## Файловые операции и callback

Функции `uv_fs_*` используют `uv_fs_t` для результата операции. При `cb == NULL` операция синхронна и блокирует вызывающий thread; с callback она выполняется асинхронно через Thread Pool. Это отличается от неблокирующего ожидания сети. Результат асинхронной операции приходит в callback, а возвращаемое значение постановки запроса сообщает о её успехе или ошибке.

## Reading/Writing files

Последовательность примера `cat`: `uv_fs_open()` получает дескриптор, `uv_fs_read()` наполняет предоставленный буфер, `uv_fs_write()` передаёт прочитанные байты в stdout, затем чтение повторяется. `uv_fs_close()` освобождает дескриптор; в примере он вызван синхронно при завершении. Для `uv_fs_read()` отрицательный `req->result` означает ошибку, ноль — конец файла, положительное число — количество прочитанных байтов. У stream API EOF представлен иначе (`UV_EOF`).

Буфер должен оставаться доступным до завершения соответствующей операции. Успешный `write` не гарантирует, что данные уже физически сохранены на диске. После использования каждого filesystem request следует вызвать `uv_fs_req_cleanup()` для внутренних ресурсов.

## Filesystem operations

Помимо `uv_fs_open`, `uv_fs_read`, `uv_fs_write`, `uv_fs_close`, семейство покрывает создание и удаление (`uv_fs_mkdir`, `uv_fs_mkdtemp`, `uv_fs_mkstemp`, `uv_fs_rmdir`, `uv_fs_unlink`), копирование и перемещение (`uv_fs_copyfile`, `uv_fs_rename`, `uv_fs_sendfile`), обход каталогов (`uv_fs_scandir`, `uv_fs_scandir_next`, `uv_fs_opendir`, `uv_fs_readdir`, `uv_fs_closedir`), сведения о файлах (`uv_fs_stat`, `uv_fs_fstat`, `uv_fs_lstat`, `uv_fs_statfs`, `uv_fs_realpath`, `uv_fs_readlink`, `uv_fs_access`) и ссылки (`uv_fs_link`, `uv_fs_symlink`).

Для изменения метаданных предусмотрены `uv_fs_chmod`, `uv_fs_fchmod`, `uv_fs_chown`, `uv_fs_fchown`, `uv_fs_lchown`, `uv_fs_utime`, `uv_fs_futime`, `uv_fs_lutime`, `uv_fs_ftruncate`; синхронизация с хранилищем — `uv_fs_fsync` и `uv_fs_fdatasync`. Все эти функции следуют общей схеме request/callback/result, но имеют разные аргументы. Их наличие не означает, что каждая операция всегда поддерживается на любой файловой системе.

## Buffers and Streams

`uv_stream_t` объединяет интерфейс потоков для TCP, TTY и pipes. `uv_read_start()` включает повторяющееся чтение, `uv_read_stop()` его останавливает, `uv_write()` ставит запись. `uv_buf_t` содержит указатель и длину, но память под данные выделяет и освобождает приложение. В примере `tee` один входной буфер копируется для двух независимых записей, чтобы его не освободили раньше завершения каждой записи. `nread < 0` обозначает ошибку или `UV_EOF`, `nread == 0` — сейчас нет данных. Ошибка выделения буфера требует явного решения об остановке чтения. Исходная страница сама помечает пример `tee` как ненадёжный; его следует читать как демонстрацию владения буферами, а не использовать как готовую программу.
